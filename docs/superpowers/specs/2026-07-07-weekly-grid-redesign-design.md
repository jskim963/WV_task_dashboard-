# 주간일정 그리드 리뉴얼 설계 (beta 전용)

> 작성일: 2026-07-07
> 브랜치: `beta` (이 기능은 beta에만 적용, master/운영에는 반영하지 않음)

## 배경 / 문제 정의

팀에서 실제로 쓰는 구글 스프레드시트 일정표(사용자 제공 스크린샷)는 여러 주가 위아래로 이어진 화면을 스크롤로 자유롭게 보고, 셀을 클릭해 바로 값을 채워 넣는 방식이다. 반면 현재 앱의 "주간일정" 화면(`Pages.weekly`, index.html)은:

1. 한 주씩만 보여주고 "이전주/다음주/이번주" 버튼으로 넘겨야 한다 — 여러 주를 이어서 훑어보기 불편.
2. 일정을 넣으려면 "일정 추가" 버튼 → 전체 모달 → 체크박스 목록에서 본인 이름 찾기 → 저장(모달 닫힘) 순서를 거쳐야 한다.
   - 본인 이름을 체크박스 목록에서 찾는 게 번거롭다.
   - 격일(비연속)로 여러 날 일정을 넣을 때마다 모달을 처음부터 다시 열어야 한다.

이 설계는 데스크탑 주간일정 화면(테이블: 행=팀원, 열=요일)을 스프레드시트에 가깝게 재구성한다. **모바일 주간일정(아코디언 스택 뷰)은 이번 범위에서 제외** — ctrl/shift 같은 키보드 modifier가 터치 환경에 없으므로 그대로 둔다.

## 1. 연속 스크롤 (여러 주)

- 고정된 주 범위(예: 이번 주 기준 이전 2주 ~ 이후 6주, 총 9주)를 하나의 스크롤 컨테이너 안에 이어서 렌더링한다. 각 주는 "구분 M/D~M/D" 라벨 행으로 구분된다.
- 스크롤 컨테이너 맨 위/맨 아래에 "이전 주 더보기" / "다음 주 더보기" 버튼을 두어, 누르면 추가로 몇 주치를 렌더링 범위에 붙인다.
  - 위쪽에 주를 추가할 때는 스크롤 위치가 시각적으로 튀지 않도록(현재 보고 있던 지점 유지) 처리한다.
- 요일 헤더(이름/월~일)는 스크롤 시 상단에 고정된다.
- 기존 "이전주/다음주/이번주" 버튼은 제거하고, "이번주" 버튼은 "이번 주로 이동"(스크롤 위치를 이번 주 블록으로 점프) 기능으로 대체한다.
- 데이터 소스, 이벤트 필터링 로직(`DB.events`, `업무보고` 타입 제외, 팀 이벤트 판별 등)은 기존과 동일하게 유지 — 여러 주를 반복 렌더링하는 것뿐, 데이터 모델은 그대로.

## 2. 셀 클릭 인터랙션

행=팀원, 열=요일인 테이블의 각 데이터 셀에 대해:

### 2-1. 일반 클릭 (modifier 없음)
- 기존 다중 선택이 있었다면 해제하고, 클릭한 셀 하나만 대상으로 팝오버를 연다.
- **팝오버는 항상 "추가" 동작이다.** 그 칸에 이미 일정이 있어도(예: 오전 출장 + 오후 미팅처럼 하루에 여러 건) 기존 항목을 지우지 않는다.
  - 이미 있는 항목들은 팝오버 상단에 각각 한 줄씩 나열되고, 옆에 ✕ 버튼으로 개별 삭제 가능.
  - 그 아래 입력창에 새 내용을 적고 유형(🔵출장/🔴휴무/🟡미팅/🟣기타) 칩을 고른 뒤 "추가"를 누르면 새 항목이 하나 더 생성된다.
  - 유형 칩을 누르면 입력창이 비어 있을 때 한해 해당 유형 이름("출장" 등)을 자동으로 채워준다(뒤에 상세 내용을 이어 적을 수 있게).

### 2-2. Ctrl+클릭 (개별 다중 선택)
- 클릭한 셀을 현재 선택 집합에 토글(추가/제거)한다. 팝오버는 즉시 열지 않는다.
- 선택된 칸이 1개 이상이면 화면에 떠 있는 액션 바("N칸 선택됨 · 일정 입력")가 나타난다.
- 선택은 행(팀원)·열(날짜)에 상관없이 임의의 조합이 가능하다 (한 사람의 비연속 날짜, 또는 여러 사람에 걸친 조합 모두 허용).

### 2-3. Ctrl+Shift+클릭 (사각형 범위 선택)
- 가장 최근의 "기준점"(마지막 일반 클릭 셀, 또는 현재 선택의 시작 셀)과 지금 클릭한 셀 사이의 사각형 블록(행 범위 × 열 범위)을 전부 선택 집합에 추가한다.
- 예: 박광원·월요일을 기준점으로 두고 Ctrl+Shift로 이영희·화요일을 클릭하면 (박광원~이영희) × (월~화) 총 4칸이 선택된다.
- 단일 행 안에서만 눌러도 동일하게 동작한다 (예: 월요일 클릭 후 Ctrl+Shift로 금요일 클릭 → 월~금 5칸).

### 2-4. 다중 선택 상태에서 "일정 입력" 클릭
- 팝오버가 열리지만 기존 항목 나열은 하지 않는다(선택된 칸마다 기존 내용이 다를 수 있으므로) — 대신 "N칸에 동일하게 입력됩니다" 안내 문구만 보여준다.
- 제목 입력 + 유형 칩 선택 후 "저장 (N건 생성)"을 누르면, 선택된 (팀원, 날짜) 조합마다 각각 독립된 일정이 하나씩 생성된다(총 N건). 기존 내용을 덮어쓰지 않고 추가된다.
- 저장 후 선택 상태는 해제되고 팝오버가 닫힌다.

### 2-5. 선택 해제 / 팝오버 닫기
- 그리드 바깥을 클릭하거나 Esc를 누르면 선택 해제 및 열려 있는 팝오버를 저장 없이 닫는다.
- 팝오버 안의 입력창에서 Enter를 누르면 저장(추가/일괄생성)과 동일하게 동작한다.

### 2-6. 선택 칸 시각 표시
- 선택된 셀은 옅은 파란 배경 + 파란 테두리로 강조한다.

## 3. 데이터/삭제 관련 설계 결정

- 새 팝오버로 생성되는 일정은 항상 **개인 단독 이벤트**다: `{id, title, date, personId, personIds:[personId], type, memo:'', createdAt}` — `dateEnd`나 여러 명 묶음은 사용하지 않는다. 기존 `DB.events` 스키마 그대로 사용, 스키마 변경 없음.
- **팀 전체 이벤트(personId=0, 모든 행에 동일하게 표시되는 것)는 이 팝오버에서 삭제할 수 없다.** 팝오버에 나열은 되지만 ✕ 버튼이 없는 읽기 전용 항목으로 표시한다. 팀 이벤트 수정/삭제는 기존 방식(캘린더 상세보기 등)을 그대로 이용한다.
- 개인 이벤트의 ✕ 삭제는 해당 이벤트 레코드를 통째로 삭제한다. (과거 모달에서 두 명 이상을 개별 선택해 만든 이벤트처럼 `personIds`에 여러 명이 들어있는 예외 케이스가 있다면, 한쪽에서 삭제해도 전체가 삭제된다 — 흔치 않은 케이스라 별도 분리 로직은 만들지 않는다.)
- 기존 "일정 추가" 버튼과 전체 모달(팀 전체 지정, 날짜 범위, 메모 등)은 그대로 유지한다. 이 팝오버는 빠른 개별 입력을 위한 **추가 경로**이지 기존 모달을 대체하지 않는다.

## 4. 범위 밖 (Out of scope)

- 모바일 주간일정(아코디언 스택) 화면 변경.
- 캘린더 월간 뷰(`Pages.calendar`) 변경.
- 팀 전체 이벤트의 편집/삭제를 팝오버 안으로 가져오는 것.
- 기존 "일정 추가" 전체 모달의 UI 변경.
