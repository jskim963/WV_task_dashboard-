# 취합리스트 기능 설계

**날짜:** 2026-07-08
**상태:** 승인됨

---

## 1. 개요

현재 팀 회신 취합 현황(요청부서/구분/제목/회신기한/담당자/비고)을 특정 담당자가 엑셀에 수기로 정리해 단체 소통방에 캡처로 공유하고 있다. 이를 대시보드 기능으로 옮겨서:

- 취합건을 구조화된 데이터로 등록·관리하고
- 취합건별로 회신 대상 팀원을 지정해 제출 여부를 체크하고
- 미제출 팀원에게 Webex로 알림을 보낼 수 있게 한다

백엔드 서버 없이 정적 HTML + Firestore + Firebase Storage로만 동작하는 기존 아키텍처를 그대로 따른다.

---

## 2. 데이터 모델

### `collections` 컬렉션 (신규)

```js
{
  id: number,                  // Date.now()
  dept: string,                 // 요청부서
  tag: '신규' | '중요' | null,  // 구분 (단일 선택)
  title: string,                // 제목
  deadline: string,             // 회신기한, 'YYYY-MM-DD'
  managerId: number,            // 취합 담당자 memberId
  memo: string,                 // 비고
  targetIds: number[],          // 회신 대상 팀원 memberId 목록
  submitted: {                  // 팀원별 제출 체크 상태
    [memberId: string]: { checked: boolean, at: number | null }
  },
  attachments: [
    { name: string, path: string, url: string }
  ],
  status: '진행중' | '완료',    // targetIds 전원 checked=true가 되는 순간 자동으로 '완료'
  lastNotifiedAt: number | null,
  createdAt: number,
  createdBy: string,            // currentUser.username
}
```

- 기존 `DB.tasks`/`DB.events`와 동일하게 단일 문서 + 배열/맵 필드 패턴을 따른다.
- `FS_COLLS`에 `'collections'`를 추가해 실시간 동기화한다.
- 완료 전환은 저장(체크 토글) 시점에 클라이언트에서 계산해 `status` 필드를 함께 갱신한다.

### 첨부파일

- Firebase Storage 경로: `collections/{collectionId}/{timestamp}_{fileName}`
- 업로드 후 `getDownloadURL()`로 받은 URL을 `attachments[].url`에 저장 (자료실 페이지와 동일한 패턴, [index.html:4355](../../../index.html#L4355) 참고)
- 목록에서 파일명을 클릭하면 해당 URL로 즉시 열기/다운로드 — 담당자가 메일로 따로 받을 필요 없음

### `settings/webex` 문서 (신규, 별도 컬렉션)

```js
{ botToken: string }
```

- `FS_COLLS` 동기화 대상에 **포함하지 않는다** — 앱 부팅 시 전체 클라이언트에 뿌려지지 않도록, "알림 보내기" 클릭 시점에만 1회 조회한다.
- Firestore 보안 규칙: 인증된 사용자만 read 가능하도록 제한 (기존 앱의 로그인 체계와 동일한 수준).

## 3. 화면 / UI 구조

### 네비게이션

사이드바에 "취합리스트" 메뉴 신규 추가 (아이콘: `checklist` 또는 유사).

### 목록 화면 (`Pages.collections`)

- 상단 서브탭: **진행중** / **완료**
  - 진행중: `status:'진행중'`인 건만, 회신기한 임박순 정렬, 기한 초과 건은 적색 강조
  - 완료: `status:'완료'`인 건만, 최신순
- 테이블 컬럼: 요청부서 · 구분(배지) · 제목 · 회신기한 · 취합 담당자 · 제출현황(`3/5`) · 비고
- 우측 상단 "+ 취합건 등록" 버튼

### 등록/수정 모달

- 입력 필드: 요청부서, 구분(일반/신규/중요 단일 선택), 제목, 회신기한, 취합 담당자(팀원 1명), 비고
- 대상 팀원 다중선택: 기존 업무 등록 폼의 `#task-assignee` 체크박스 패턴 재사용 ([index.html:2459](../../../index.html#L2459) 참고)
- 첨부파일 다중 업로드

### 상세 화면 (행 클릭 → 모달/패널)

- 상단: 제목 / 요청부서 / 회신기한 / 취합 담당자 / 비고
- 대상 팀원 체크리스트: 이름 + 체크박스(제출 여부) + 체크 시각
- 미체크 인원 요약 + **"미제출자에게 Webex 알림 보내기"** 버튼
- 첨부파일 목록 (업로드 / 다운로드 / 삭제)

## 4. Webex 알림 연동

### 사전 설정 (관리자, 최초 1회)

1. Webex 개발자 포털에서 **알림 전용 봇**을 새로 생성 (메시지 발송 권한만 부여, 다른 권한 최소화)
2. 발급받은 Bot Access Token을 설정 페이지의 기존 "Webex 연동" 입력창(현재 비활성화 상태, [index.html:976-978](../../../index.html#L976-L978))을 활성화해 입력 → `settings/webex` Firestore 문서에 저장

### 발송 흐름

1. 취합건 상세에서 담당자가 "미제출자에게 Webex 알림 보내기" 클릭
2. 그 시점에 `settings/webex`에서 봇 토큰을 1회 조회 (미리 로드하지 않음)
3. 미체크 대상 팀원 각각의 `DB.members[].email`을 이용해 Webex REST API를 브라우저에서 직접 호출
   `POST https://webexapis.com/v1/messages` — `{ toPersonEmail, text }`, `Authorization: Bearer {botToken}`
4. 메시지 형식: `[취합리스트] {요청부서} · {제목} — 회신기한 {deadline}까지 제출 부탁드립니다.`
5. 발송 완료 시 해당 취합건의 `lastNotifiedAt` 갱신, "N명에게 알림 발송완료" 토스트 표시
6. 발송 실패(개별 수신자) 시 실패 대상만 토스트로 안내하고 나머지는 정상 처리

### 보안 처리

- Bot Token은 소스코드(index.html)에 하드코딩하지 않고 Firestore 문서로만 저장 → git 이력에 남지 않음
- 해당 문서는 앱 부팅 시 자동 동기화되지 않고, 알림 발송 시점에만 조회 → 노출 시간 최소화
- 전용 봇은 메시지 발송 권한만 있어, 토큰이 노출되더라도 피해 범위가 "이 봇 이름으로 메시지 발송 가능" 수준으로 제한됨
- 내부 로그인 팀원만 접근 가능한 내부 툴이라는 전제하에 수용 가능한 수준의 위험으로 판단 (더 안전한 방식은 8절 참고)

---

## 5. 권한

로그인한 팀원 누구나 취합건 등록·수정·팀원 체크·알림 발송이 가능하다. 기존 대시보드의 권한 모델(로그인 = 팀 내부 신뢰 기반)을 그대로 따른다.

---

## 6. 완료 처리

- `targetIds`의 모든 memberId가 `submitted[id].checked === true`가 되는 순간, 저장 로직에서 자동으로 `status: '완료'`로 전환
- 완료된 건은 목록 화면의 "완료" 탭으로 이동하고 "진행중" 탭에서는 더 이상 보이지 않음
- 별도의 수동 "완료 처리" 버튼은 두지 않는다 (전원 체크 = 완료)

---

## 7. 범위 외 (이번 구현에서 제외)

- **자동/예약 알림**: 백엔드/크론이 없는 정적 앱 구조상, 마감 임박 시 자동으로 알림을 보내는 기능은 이번 범위에 포함하지 않는다. 알림은 담당자가 버튼을 눌러 수동으로 발송하는 방식만 지원한다.
- **Firebase Cloud Functions 프록시**: 토큰을 서버 측에만 두는 더 안전한 방식은 별도 백엔드 구축이 필요해 이번 범위에서 제외한다. 필요 시 후속 작업으로 분리한다.
- **역할 기반 세분화된 권한 제어** (담당자만 수정 가능 등): 이번에는 로그인 팀원 전원 동일 권한으로 시작한다.

---

## 8. 테스트 계획

- 취합건 등록 → Firestore에 정상 저장되는지
- 대상 팀원 체크/해제 → `submitted` 갱신 및 제출현황(`n/m`) 표시 정확성
- 전원 체크 시 자동으로 완료 탭 이동
- 첨부파일 업로드 후 목록에서 클릭 시 다운로드/열람 정상 동작
- Webex 알림 발송 버튼 클릭 시 미체크 대상에게만 호출되는지 (모킹 또는 테스트 봇으로 검증)
- 봇 토큰이 `FS_COLLS` 동기화 목록에 없어 앱 부팅 시 네트워크 탭에 노출되지 않는지 확인
