# @멘션함 설계

> 작성일: 2026-07-15

## 배경

업무현황 코멘트와 센터별 특이사항에 자유 텍스트를 입력할 수 있지만, 특정 팀원을 콕 집어 알리는 방법이 없다. `@이름`을 입력하면 그 사람이 나중에 대시보드에서 자신이 언급된 내역을 시간순으로 확인할 수 있게 한다.

대시보드의 "개인 메모장" 카드 자리(`index.html:495-502`)를 이 "멘션함" 카드로 대체한다. 메모 기능 자체는 사라지지 않고 `2026-07-15-utility-panel-design.md`의 우측 유틸리티 패널로 이전된다.

## 범위

- 대상 코멘트/노트: **업무현황 코멘트**(`DB.tasks[].comments`, `addComment()`) + **센터별 특이사항**(`DB.centers[].operationNotes`, `addOperationNote()`) 두 곳만.
- 기안서 댓글, 공지사항 댓글, 프로젝트 댓글은 이번 범위에서 제외한다. (이미 `authorId`/타임스탬프를 갖추고 있어 나중에 같은 헬퍼로 쉽게 확장 가능하지만, 지금은 만들지 않는다.)
- 취합리스트(collections)는 코멘트 필드가 없어 대상이 아니다.

## 데이터 설계: 별도 컬렉션 없이 계산(derive)

새 Firestore 컬렉션을 만들지 않는다. 이미 클라이언트에 로드되어 있는 `DB.tasks` / `DB.centers`의 코멘트 텍스트에서 그때그때 멘션을 계산한다.

**이유**
- 스키마 마이그레이션이 필요 없음
- 이 기능이 생기기 전에 우연히 "@이름"을 포함해 작성된 과거 코멘트도 자동으로 소급 반영됨
- 쓰기 시점에 별도 인덱스 문서를 만들 필요가 없어 이중 저장/경합 위험이 없음
- 대상 업무/센터가 삭제되면 멘션도 자동으로 함께 사라짐(별도 정리 로직 불필요)

**정렬용 타임스탬프 추가**

두 저장 함수에 숫자 타임스탬프 필드를 추가한다(기존 필드는 유지, 하위 호환):

- `addComment()` (`index.html:2660`): `t.comments.push({author, text, time: timeStr, ts: Date.now()})` — `ts` 필드만 추가
- `addOperationNote()` (`index.html:4075`): 이미 `date: Date.now()`가 있으므로 그대로 정렬 키로 사용(변경 없음)

`ts`/`date`가 없는 과거 코멘트는 정렬 시 가장 오래된 것으로 취급해 목록 맨 아래로 밀린다.

## @이름 자동완성

`#comment-input`(업무 코멘트 입력)과 `#ops-note-input-${centerId}`(센터별 특이사항 입력, 센터마다 동적 생성) 두 입력창에 공용 헬퍼를 붙인다.

- `attachMentionAutocomplete(el)`: `input` 이벤트에서 커서 직전 `@` 이후 텍스트를 추출 → `DB.members` 이름 중 해당 문자열로 시작하는 항목을 필터링 → 기존 `assignee-dropdown-panel` 스타일의 드롭다운을 입력창 바로 아래 표시
- 드롭다운에서 이름 선택 시 커서 위치의 `@부분입력`을 `@전체이름 `(뒤에 공백 포함)으로 치환하고 드롭다운을 닫음
- `#comment-input`은 페이지 로드 시 1회 바인딩, `#ops-note-input-*`는 센터 상세 렌더링 시점마다 바인딩(동적 ID이므로)

## 멘션 계산 및 렌더링

**`getMyMentions()`**
1. `DB.tasks`를 순회하며 각 `comments[]` 텍스트를 정규식으로 스캔
2. `DB.centers`를 순회하며 각 `operationNotes[]` 텍스트를 동일하게 스캔
3. 정규식은 `DB.members`의 이름 목록으로 매 호출 시 동적 생성: 이름을 길이 내림차순으로 정렬 후 정규식 특수문자를 이스케이프하고 `@(이름1|이름2|...)` 형태로 결합 (긴 이름이 짧은 이름의 부분 문자열인 경우 오매칭 방지)
4. 매칭된 이름이 `currentUser.name`과 일치하는 코멘트만 수집: `{sourceType: 'task'|'center', sourceId, snippet, authorName, ts}`
5. `ts` 내림차순 정렬 후 반환(상위 N개, 예: 20개로 제한)

**대시보드 카드 (`Pages.dashboard`, 기존 Panel 5 자리)**
- 제목 "멘션함", 항목별로 출처 아이콘(업무/센터 구분), 코멘트 스니펫(긴 경우 말줄임), 작성자 이름, 상대 시간("3시간 전") 표시
- 언급이 없으면 "아직 멘션된 내역이 없습니다" 같은 빈 상태 문구
- 항목 클릭 시 `sourceType`에 따라 `showTaskDetail(sourceId)` 또는 `openCenterDetail(sourceId)` 호출 → 원본 위치로 이동

## XSS 처리

코멘트 스니펫을 `innerHTML`로 렌더링할 때는 프로젝트 컨벤션대로 `escapeHtml()`을 반드시 거친다.

## 알려진 제약 (의도적으로 범위 밖)

- 읽음/안읽음 상태 추적 없음 — 클릭 여부와 무관하게 항상 전체 목록 표시
- 기안서/공지사항/프로젝트 댓글은 멘션 대상이 아님(향후 확장 시 `getMyMentions()`에 소스만 추가하면 됨)
- `@이름`이 두 명 이상 동명이인일 경우 이름만으로는 구분 불가(현재 팀원 데이터에 동명이인 처리 로직이 없으므로 기존 한계를 그대로 이어받음)

## 테스트/검증

- `node -e` 문법 체크 스크립트로 구문 오류 확인
- `getMyMentions()` 정규식 매칭을 대표 케이스(이름이 다른 이름의 부분 문자열인 경우, 여러 명 언급, 멘션 없음)로 콘솔에서 수동 확인
- 브라우저 프리뷰 검증은 기본 생략, 요청 시에만 수행
